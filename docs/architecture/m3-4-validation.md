# M3.4 implementation and validation

Starting HEAD: `807783eb00256b9c8e2da21846dd5ac529ad7a4d`. Existing local changes to `package-lock.json` and `.vscode/` are outside this milestone's commits.

## Checkpoint A

The cropper used one error variable for initialization, crop validation and output failure, then derived readiness as `isReady && !error`. A small crop therefore disabled its correction controls. Readiness now excludes only fatal initialization failure. Crop events revalidate a rejected selection; keyboard resizing stays available. Output failures retain a retryable Done action.

Selected photos can reopen the preserved source with the accepted crop. Cancel preserves the accepted derivative; confirmation replaces it after encoding succeeds. The existing scoped IndexedDB draft carries source, derivative, pending source and crop state. Ordinary acquisition no longer displays generated filenames or sizes.

New automatically unnamed photo items store an empty name. Render-time dictionaries supply the fallback in lists, detail, photo alt text and collection selection. Historical literal names are never rewritten. Photo-less creation and clearing a previously named item's name still require a meaningful name; an already unnamed item can edit other fields without a forced rename, even after its last photo is removed. Search matches actual stored metadata and inventory numbers, and the current localized unnamed fallback without storing that translation; name sorting places empty values together with a stable UUID tie-break. Readable archive filenames already have a neutral `Item` fallback; import accepts empty stored names. Add Item has a distinct Save item action in all five dictionaries.

Initial validation: typecheck, lint and the existing 56 unit tests passed. Two synthetic Microsoft Edge scenarios passed: invalid crop correction, keyboard resizing, repeated source edit/cancel, IndexedDB reload recovery, saved dimensions, and five-language crop errors/unnamed display with literal-name preservation. Final checkpoint A checks: typecheck, lint, 57 unit tests and production build passed. All 11 affected Edge scenarios passed (including existing marker/pixel geometry and browser-restart draft tests, plus injected canvas-failure retry). The existing Next.js ESLint-plugin detection warning remains.

Reordering temporarily uses a disjoint order range, then writes contiguous positions. Primary deletion promotes the first surviving ordered photo.

Additional photos never replace siblings. A replacement creates a new media UUID and moves only the target position/primary state and explicit collection-cover references in one transaction; sibling UUIDs and bytes stay stable. Old files survive until commit. Deleting a referenced image deliberately resets that collection cover via the existing trigger; its confirmation explains this. All member photos are now eligible covers. Reads validate inventory/item/media ownership and generated private paths, including source routes. Cleanup refuses a live referenced asset, protecting ambiguous commit acknowledgements.

The detail UI retains one compact viewer and adds an ordered thumbnail strip, primary selection, accessible earlier/later buttons, per-image crop/replacement and confirmed deletion. A separate acquisition control adds one photo at a time with the existing camera/file/crop flow; there is no batch queue or duplicate item Save. Recoverable upload errors retain the selected File and prior persisted gallery. The multipart limit is 22 MiB to accommodate separately bounded 10 MiB derivative/source files plus form overhead.

Typecheck/lint and 61 unit tests passed, including synthetic pre-0011 backup/migration preservation, duplicate-order/primary constraints, foreign-inventory attempts, failed replacement rollback and non-primary cover transitions. The added concurrent-addition test also passes: 62 unit tests pass with the default `npm test` command and a clean exit. One Windows threaded-worker run emitted all successful assertions but exited with a native access violation; it is not counted as a successful process run. Typecheck, lint and production build pass. Four affected Edge scenarios pass across focused runs, including three-photo order/primary/crop/deletion and existing cover and five-language recovery workflows. ## Checkpoint D

The toolbar uses native selects with intrinsic selected-label sizing and a flexible always-visible search. A local chevron avoids native-arrow width differences; reserved clear geometry remains stable when only a search becomes active. Label changes may intentionally reflow controls. Categories use consistent one-line chips, bounded long labels, full accessible names/titles and independent links. Missing row photos use a neutral local SVG icon.

A first-party browser cookie stores the sidebar preference and seeds server rendering, avoiding an expanded hydration flash. Only a short click-triggered interval animates sidebar width; resizing does not enable animation and reduced motion overrides it. Icons retain accessible names/tooltips, the brand mark stays visible and mobile retains labels. Dialogs clip the outer radius and scroll padded inner regions; action rows stay reachable. Hover/pressed/disabled feedback uses color, border and opacity without lift.

Collection cover code previously let the generic detail-image auto dimensions override the full cover image box. The corrected closed viewer fixes both image-box dimensions and centers contained pixels inside a maximum 560 by 220 frame. Full viewing still contains the complete image. Portrait, landscape, square and extreme-ratio synthetic Edge fixtures verify centered bounds and stable height.

Currency choices have one bundled code/unit source and five complete label dictionaries. Locale is only an initial recommendation; manual choices stay fixed. Blank prices store null amount/currency. Decimal strings convert with integer arithmetic. Migration 0012 adds an explicit exponent defaulting to 2 for every historical price; unchanged codes retain that exponent when editing. This protects even unknown historical codes from reinterpretation. New ISO JPY/KWD use 0/3, and ISO HUF remains 2 despite the observed Node Intl default of 0. Revision 6 and CSV preserve the stored exponent; revisions 2–5 adapt to 2. See [source reconciliation](../product/m3-4-design.md).

Focused validation passed 40 width/language combinations, sidebar keyboard/persistence/reduced-motion checks, 360px dialog scrolling, locale/manual-currency/save/edit/ZIP restoration and four cover ratios. The unit suite reached 70 passing tests. The first complete 37-scenario regression run found two outdated assertions, a too-short wait for a larger synthetic import, and a lost screen-reader success announcement when a replaced photo remounted. The announcement is now owned by the persisted gallery; all four previously failing scenarios now pass in focused reruns; typecheck, lint, 70 unit tests and production build pass. The complete final regression is recorded in checkpoint E. Unnamed fallback search is also explicitly localized without writing translated names.
