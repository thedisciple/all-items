# Proposed v0.1 compatibility policy

Status: candidate release policy, not a declaration that v0.1 or a hosted pilot has shipped. Physical device, accessibility, security and recovery acceptance remain open.

- Runtime: Node versions declared in package.json (`^20.19.0`, `^22.13.0`, or `>=24`); CI is authoritative for the specific tested version. Dependencies and fonts are bundled locally. Use a production build for deployment and loopback as the default binding.
- Browser targets: current stable Edge and Chrome on Windows, Safari on iOS/iPadOS, Chrome on Android and current Firefox. The supported matrix is provisional until actual devices, keyboard/screen-reader paths and camera/zoom/touch acceptance pass. JavaScript and first-party storage are needed for editing and recoverable drafts; denied/quota storage must produce a recoverable warning. Local list-view preferences are browser- and inventory-scoped and are excluded from ZIP and installation backups.
- Secure contexts: local loopback is recognized as potentially trustworthy; non-loopback HTTP is not an acceptable way to expose the inventory or use camera. Production access requires HTTPS plus implemented per-user authorization and origin/host controls.
- Upgrades: stop app processes, make and verify an installation backup and perform an isolated restore drill before upgrading or applying migrations. Ordered additive migrations and logs run only through startup or explicit migration, never build/test. Do not assume rollback of a migrated database; restore to a separate directory with a matching app version after review.
- Portable ZIP: experimental revision 6 is current. Tested revision 2–5 import adapters are retained; revision 1 and unknown revisions are rejected. A future public compatibility commitment needs explicit versioning and fixture coverage before release. Installation backup format 1 is distinct, tied to the matching migration/application set, and does not include browser drafts.
- Current scope: one private local installation. P1 local separately owned accounts are implemented. No hosted pilot, shared workspace roles or public multi-user deployment is implied. Pilot requirements and manual device checklist are in [the device/pilot runbook](m4b-3-device-pilot.md).
