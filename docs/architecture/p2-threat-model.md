# P2 security review checklist

This is an implementation review, not an independent penetration test. The trusted boundary is a single loopback-bound Next.js process behind an explicitly configured HTTPS reverse proxy. Browser input, cookies, URL identifiers, archive bytes, forwarding headers and Telegram assertions are untrusted. The Windows service account and its private data directory are trusted. No public endpoint has been enabled.

| Entry point | Confirmed control | Remaining gate |
| --- | --- | --- |
| All pages, Server Actions and route handlers | Exact Host/origin policy; proxy mode requires an installation secret and pinned forwarded host/protocol/port; local mode requires HTTP loopback. Middleware rejects hostile requests before rendering. | Independent review of proxy topology and any future Next upgrade. The secret is a bearer capability: protect the private Caddy/app configuration and loopback host. |
| Password sign-in and sessions | Password scrypt, generic errors, SQLite-backed account and installation attempt budgets, HMAC-stored opaque session tokens, absolute/idle expiry, HttpOnly/SameSite Strict and HTTPS Secure cookies, server-side revocation/disable. | Distributed abuse controls and password-recovery identity verification before broader deployment. |
| Inventory, item, stock, collection, category, media, source and cover paths | `authorizeInventory` checks the actor against `inventory_owners`; an inventory UUID never grants ownership. Controlled media routes use identifiers, private paths and no-store. Legacy unscoped routes reject or route through authorization. | Repeat cross-account adversarial checks under production HTTPS after any new route. |
| Import/export and photo staging | Inventory context is explicit; ZIP preview has bounds/checksums/path validation, restore uses generated paths/transaction/journal; media processing strips metadata; export/private download uses no-store. | Review upload rate and whole-request limits at the final proxy; run large-body denial tests. |
| Installation backups and account CLI | Backups require installation admin; local CLI is not exposed by HTTP. Verification and isolated restore drills are available. | Restrict NTFS access, schedule and monitor copies, and choose protected off-machine storage. |
| Browser drafts | IndexedDB remains browser-local, inventory-scoped and excluded from portable archives. | Use separate browser/OS profiles on shared devices; local profile access can inspect drafts. |
| Optional Telegram OIDC and invitations | Config-gated exact HTTPS callback, pinned issuer/endpoints, Authorization Code + PKCE/nonce, RS256 JWKS signature checks, five-minute one-use state, cookie binding, one-hour single-use invite, transactional identity collision checks, same-session link confirmation and password-confirmed unlink. No profile/phone/chat scopes. | Live BotFather/domain/TLS integration and provider-outage behavior on actual devices remain untested. The installation-wide start budget is not distributed; review DoS and recovery before exposure. |
| Static and optimized assets | Shared Next image optimizer is denied; private images use no-store controlled routes. Security headers deny framing and plugins. | CSP intentionally does not constrain Next inline script/style; tighten only after a nonce-compatible production review. |
| Funnel loopback adapter | Caddy binds only to 127.0.0.1; exact incoming Host, pinned upstream origin/secret, replaced forwarding assertions, bounded bodies and header/body timeouts. TLS terminates at the retained Tailscale node. | Real Funnel/external transport, account/policy, denial-of-service and physical-device review remain open. Local processes can reach the adapter; OS identity/NTFS boundaries remain trusted. Public visitors still require app authentication. |
| Data-page backup summary | Bounded completion metadata listing; no SQLite worker or media hashing during ordinary navigation. Admin-only page/actions; explicit verification is unchanged. | Recorded completion is not current integrity. Schedule full verification and verify before recovery; metadata failure must stay visible. |

The synthetic HTTPS proxy test covers legitimate login, secure cookie, origin/host/forwarded-header spoofing, direct backend bypass and image optimizer denial. A correct application response is not evidence that the router, DNS, TLS certificate renewal, operating-system account, backups or real devices are ready. See [P1 authority map](adr-p1-local-identity.md) and [deployment runbook](p2-deployment.md).

## M4E pre-invitation disposition

Implementation self-review, 2026-11-14; **independent approval is pending**. No P0 was identified; that is not a claim that none exists. Unchanged ownership/origin/media/archive/pagination boundaries retain existing synthetic evidence; no migration or authorization bypass was added.

| Finding | Severity / disposition | Evidence and remaining action |
|---|---|---|
| Telegram link/unlink could hash passwords before reserving an attempt budget | P1, fixed | Persistent reservation before scrypt: five attempts per account and thirty per installation per 15 minutes, separate from login. Failed inputs consume budget. Reopening SQLite cannot reset it; expiry is tested. Existing five-language throttling feedback is reused. Review combined login/reauth/Telegram-start DoS independently. |
| Release controller read state before taking the operation lock | P1, fixed | State is loaded/strictly parsed inside the exclusive lock. Concurrent commands refuse; malformed state fails closed. Crash lock/latch requires inspection, never automatic stealing. |
| Emergency sharing closure depended on valid state/data/journal | P1 operational, fixed | Scoped Caddy stop precedes those reads; journal failure is reported after closure. Service permissions/config must still be valid. Verify external unreachability; Funnel registration can remain. |
| Status treated recorded SHA as deployed identity | P2 operational, fixed | Bounded independent health reads and service binding comparison; observed/recorded/checkout SHA separated, cached acceptance labelled. Legacy baseline remains unknown. |
| Legacy installation has no trustworthy identity/marker | Gate preserved; Option B selected | Fresh empty generated data, verified backup/drill, separate runtime. Old data is never stamped/migrated. Approved first activation captures legacy pointer; unknown legacy code cannot be called verified rollback. |

Passwords use scrypt N=131072/r=8/p=1 and random salts; opaque session tokens are HMAC-stored with an installation-local key. Sessions have eight-hour absolute/thirty-minute idle limits. Same-installation restart retains valid sessions/key; restoration without the key invalidates old tokens. Local `auth revoke`, `disable`, `revoke-all` remove sessions; lookup checks disabled state. `reset` restores password fallback and revokes sessions; owner disable is refused. No public reset/registration endpoint exists. Local identity recovery needs operator review.

Telegram is hidden without credentials, fails preflight if partial, and requires exact HTTPS proxy mode when configured. Bare login cannot create arbitrary accounts: signed subject plus an unexpired single-use invitation creates a non-admin account without inherited inventory. Invites expire in one hour and are revocable; five-minute flows are consumed before exchange. Linking requires the original valid session, current password and same-session confirmation; unlink rechecks current password hash/enabled account. Synthetic signed-provider tests are not live acceptance. Owner must reconfirm BotFather Login Widget Allowed URLs (exact origin and `/auth/telegram/callback`), private Client ID/Secret and default RS256 against [official Telegram instructions](https://core.telegram.org/bots/telegram-login), reviewed 2026-11-14. Verify real callback, replay denial, password fallback, cancel/unlink and provider outage after approval. No phone/chat scopes.

Images remain bounded to 10 MiB, 12,000 pixels per side and 40 MP; intake/staging/request budgets are independent. Metadata-stripped media, sources/covers and archive routes retain inventory authorization/no-store. Caddy time/body limits and normalization queues do not provide per-user disk quotas, distributed abuse protection or an SLA. Review repeated authenticated upload/archive/backup abuse and large-body denial before broader exposure; no speculative limiter rewrite is included.

Private data/backups/runtime/journals require intended owner/service/admin NTFS ACLs; Node mode 0600 alone is not an NTFS guarantee. Inspect broad Allow entries (Everyone, Authenticated Users, Builtin Users), intended service access and restored paths without publishing identities/ACL dumps. Read-only inspection of existing synthetic data/config found no such broad grants; inherited/new storage ACLs, service-specific access and off-machine recovery still require review. App/Caddy are non-LocalSystem and Manual; Tailscale is Automatic. No ACL/account/startup mode was changed and cold reboot remains unverified. Recover private runtime/session-key material separately from data manifests.

Before invitations, independent reviewer examines `src/auth`/middleware, inventory ownership callsites, media/staging/archive boundaries, `src/operations`/PowerShell adapter, P1/P2 adversarial and release recovery tests. Require approved service/exposure actions, external TLS/two-user checks, live Telegram if enabled, and [physical acceptance](../product/m4c-device-acceptance.md) on Windows, Android Wi-Fi/mobile data and independent-network iPhone. Keep synthetic feedback and rollback copies private. CI/self-review alone cannot close this gate.
