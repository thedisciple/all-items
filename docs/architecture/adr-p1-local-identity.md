# P1 local identity and ownership

Decision: a bounded, local credential/session implementation using Node's maintained crypto primitives and SQLite. No external identity provider or registration/reset HTTP API. This deliberately small implementation requires ongoing review; passing tests is not an independent security audit. Next.js recommends authentication libraries in general; this local CLI-provisioned scope avoids a large adapter/provider surface. Reconsider a maintained provider library before adding federation, MFA, shared roles or public deployment.

Passwords use Node scrypt (N=131072, r=8, p=1, 64-byte key, independent random 16-byte salts, constant-time comparison), following OWASP's scrypt alternative because Argon2id is not a stable built-in across the declared Node runtimes and scrypt avoids another native packaging dependency. Do not reduce cost for tests. Password input is bounded. Login reserves persistent per-account and installation-wide attempt budgets before hashing, with generic failure states; this is local SQLite throttling, not a distributed service. Provisioning, password reset and revocation are local OS-admin CLI operations with hidden password input.

Opaque 256-bit session tokens are issued only after password verification, expire absolutely and on inactivity, and can be revoked. Only HMAC token digests live in SQLite. An installation-local random session key stays outside Git and portable/installation archives. A restore into a new directory creates a new key and invalidates old browser tokens. Cookies are HTTP-only, SameSite Strict, path /, with Secure determined by the explicitly configured trusted origin. P1 permits HTTP only on loopback; it does not trust forwarding headers to determine identity, transport, host or rate-limit keys. Login rotates identity, logout revokes the server record. Private responses are not shared-cacheable; the unused shared Next image optimizer is blocked.

Migration 0014 adds users, sessions, login budgets and a one-owner-per-inventory relation. It attaches all existing workspaces to a reserved, disabled original-owner identity without modifying item, stock, category, collection, media, historical timestamp or portable data. No default password is created. Local owner bootstrap activates that identity atomically; an interrupted bootstrap remains disabled and can be retried. New accounts start without inventories. New and imported inventories receive the authenticated user's ownership in the same write transaction. Unowned workspaces fail closed. There is no sharing/admin override for another user's ordinary inventory operations.

Request identity comes only from server session lookup, never client props, cookie inventory preference or UUID. Inventory reads/writes go through a shared ownership check; custom-client archive/import/delete boundaries perform the same check on their actual database. Installation backup controls require installation admin and are never exposed to ordinary testers. Trusted offline recovery/startup workers use an explicit, scoped server-only maintenance capability; no environment switch disables authentication. Maintenance is not exported as a Server Action or HTTP endpoint.

Before migration of the real installation: stop app writers, create/verify a private format-1 backup, rehearse restore to an isolated directory, then compare original rows/media hashes and SQLite integrity/foreign keys after the additive migration. Rollback means restoring the verified backup with the matching application version into a separate directory; do not reverse SQL in place. Keep old migration/installation backups.

## Protected entry-point map

| Entry point | Authority and exceptions |
| --- | --- |
| `/`, inventory layout/pages, legacy item/collection/data redirects | Verified session, filtered owned inventory list; route ownership before loaders. Login, the origin-checked language preference action, static assets and generic error/Gone responses without inventory data are public exceptions. |
| `actions.ts` item, stock, categories, collection membership/cover and gallery actions | Resolve owned inventory, then shared domain ownership check and resource-in-inventory validation. |
| `inventory-actions.ts` switch/create/rename/delete/sort | Verified user; owner-scoped selection/names; new owner relation in the transaction; delete scoped backup/cleanup journal. |
| `creation-actions.ts` stage/finalize and receipts | Ownership before parsing/reading/staging, context/command match and operation hash/receipt validation. No staging/receipt download endpoint. |
| Canonical and legacy media GET handlers | Verified ownership plus item/collection/media relation, private generated paths; thumbnail, source and display share the same authority. |
| Canonical and legacy ZIP/CSV GET; canonical inventory import preview/restore POST | Verified inventory ownership before work; exact trusted request origin for mutations; import assigns new target to caller. ZIP never carries users/sessions/ownership. Legacy unscoped import POSTs return a static 410 without reading or writing inventory data. |
| Data page and `backup-actions.ts` | Ordinary owned ZIP/CSV remain available; installation-wide backup listing/create/verify require installation admin. CLI retains OS-admin authority. |
| Private filesystem cleanup and startup journals | Generated paths and reference checks; request cleanup checks ownership; offline global recovery is explicitly scoped maintenance only. |
| Browser drafts/preferences/camera/file picker | No server authority. Inventory-scoped browser data must not be restored into a foreign account; server rechecks on upload/commit. Shared-device browser storage is not protection from an OS/browser-profile user. |
| Login/logout | Public login with exact origin, throttling and generic errors; logout requires valid origin and revokes cookie token. No registration, public reset, maintenance or dev endpoint. |

P2 must independently review request boundaries, session/credential handling, proxy/TLS policy, adversarial tests, backups, device acceptance, process reliability and rollback before any LAN/public listener or URL is enabled.
