# M3.4 interaction decisions

## Tasks and evidence

An owner needs to capture several views of one object, identify its primary thumbnail, correct one crop and recover from an error without losing other work. Lists must remain easy to scan with long category names at 360–1440px. The brief reports a cropper dead end, oversized filters, broken category words, wide off-center covers and mixed motion. Those reports are acceptance evidence; actual code and synthetic browser measurements establish mechanisms separately.

MoneyRS screenshots and the VS Code concept are user-observed interaction references, not supplied source images in this execution. They suggest explicit sidebar controls, quiet hover feedback, readable currency choices and possible future release notes/shared-group organization. No backend, security, accessibility or usability claims follow from those screenshots. No personal screenshot or inventory content was sent externally. AliExpress product galleries are an idea for selecting several object views; its appearance, promotions and trade dress are not a specification.

Verified external basis: [VS Code's layout documentation](https://code.visualstudio.com/docs/configure/custom-layout) describes explicit sidebar visibility controls. [ECMA-402 CurrencyDigits](https://402.ecma-international.org/13.0/#sec-currencydigits) defines currency fraction digits from ISO 4217 data. These establish documented capabilities, not measured task success for All Items.

## Alternatives and chosen behavior

- **Filters:** a persistent intrinsic wrapping toolbar keeps frequent category/status/sort tasks one action away and preserves the existing URL/history workflow. A Filters disclosure saves a little initial height but adds an opening action and focus/history states. An always vertical layout wastes horizontal space. Choose native persistent controls with widths based on their selected labels and a flexible visible search field; wrap only as space requires. Retain a reserved clear action.
- **Categories:** keep independent links beside the item identity. Reserve a flexible category row when columns become narrow. Use consistent one-line chips; exceptional long custom labels have bounded ellipsis, a full accessible name and native title. Words do not split. No generated concept is needed to resolve these concrete layout constraints; inspect the implemented synthetic layouts instead.
- **Sidebar:** store a browser-local preference, keep a small brand mark and named icon links when collapsed, and leave inventory switching in the header. Animate only a user toggle for a short interval. Mobile retains usable labeled navigation; reduced motion suppresses animation. No fake account/avatar is added.
- **Media:** one contained selected image, restrained ordered thumbnails and per-photo actions. New photos use the existing one-at-a-time camera/file/crop workflow. There is no upload queue or second item Save. Replacing one image moves its selected cover reference; deleting it resets that cover explicitly.
- **Covers:** use a bounded centered frame with contain rather than a full-width mostly empty banner. Overview and detail retain their selected image/emoji/default identity; the full viewer remains available.
- **Currency:** a locale suggestion is a heuristic, not residence. A manually chosen code stays fixed across locale changes; an unchanged suggestion may follow locale. Last-used ranking is not implemented. Blank prices persist null currency. Parse decimal strings exactly using pinned ISO minor units, and store each amount’s exponent explicitly. Never convert historical amounts; migration 0012 marks all pre-existing values as hundredths, including unknown historical codes. New JPY amounts use exponent 0 and KWD 3, while existing HUF stays 2. Historical unknown codes remain representable when editing.
- **Motion and scrolling:** consistent color/border/opacity feedback, no lift/bounce, visible focus and truthful disabled/pending states. Scroll inside rounded dialog frames with safe padding and a recognizable native scrollbar. Header and final actions remain reachable.

## Currency source reconciliation

The [SIX ISO 4217 List One XML](https://www.six-group.com/dam/download/financial-information/data-center/iso-currrency/lists/list-one.xml), published 2026-09-17 and fetched directly on 2026-10-30, reports minor units 2 for the supported RSD/UAH/CNY/RUB/USD/EUR/GBP/HUF/CHF/CAD/AUD, 0 for JPY and 3 for KWD. This is the bundled storage table; runtime network access is unnecessary.

Verified local finding: Node 24.20.0 Intl reports HUF maximumFractionDigits 0. [Unicode CLDR supplemental currency data](https://github.com/unicode-org/cldr/blob/main/common/supplemental/supplementalData.xml) also declares HUF display digits 0 and separate cash rounding. A formatter default is therefore not a safe storage-unit contract. All Items pins ISO units for new amounts and stores the exponent alongside each amount. The old implementation used hundredths for every supported currency; additive migration 0012 preserves that interpretation for every historical row, even a legacy unknown/JPY code. No amount, currency code or historical price bytes are rewritten. An unchanged currency retains its stored exponent during editing. CSV and ZIP use that explicit exponent. A future unit-policy change needs a deliberate compatibility/migration decision.
